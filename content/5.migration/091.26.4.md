## Overview

Minecraft 26.4 brings changes to client registries and screen input handling, with slots now being regular widgets.

### Version Catalog

::latest-versions{minecraft=26.4 allowSnapshots=true}
::

## ⚠️ Known Issues

- Cloth Config support is currently disabled.
- Fabric Permissions API integration is currently disabled.
- Custom block state models are currently disabled.

## Breaking Changes

### Fluid and energy amounts now use `long`

`FluidTank` and `EnergyStorage` now use `long` for amounts, capacities, transfer limits and the return values of `fill` and `drain`.

### Removed `BalmArgumentTypeRegistrar`

Argument types can now be registered directly into their registry. `Balm.argumentTypes(...)` and `BalmModule#registerArgumentTypes(...)` have also been removed. Move these registrations to the generic registry registration API.


### Temporarily removed command permission helpers

`BalmCommands.requirePermission`, `requireAnyPermission` and `requireAllPermissions` are temporarily removed while we observe Fabric's and NeoForge's response to Vanilla changes around permissions.

For vanilla permission-level checks, use `Commands.hasPermission(...)`, for example:

```java
Commands.literal("example")
        .requires(Commands.hasPermission(CommandPermissionLevels.LEVEL_OWNERS));
```

### Container screen accessor changes

If you use `AbstractContainerScreenAccessor`:

- `getHoveredSlot()` is now `callGetHoveredSlot()`.
- `callExtractSlot` and `callIsHovering` have been removed, since slots are now regular widgets.

### Kuma: replaced `ignoreScreenFocus` with a sensible default and optional input predicate overrides

Screen key handlers now run by default unless the screen is currently capturing input, as reported by `Screen#isInputCaptured()`. Previously, any focused element prevented handling unless `ignoreScreenFocus()` was enabled.

The new default should be fine to cover most cases - if you need to override it e.g. to have your key run even if the screen is capturing input for a text field, you can:

```diff
-.ignoreScreenFocus()
+.withScreenInputPredicate(event -> true)
```

## Other Changes

### Fluid unit conversion

Fabric uses different fluid units than NeoForge. You can now use the new `FluidAmount` type instead of hardcoding fluid quantities:

```java
long capacity = FluidAmount.buckets(1).toPlatform();
long transferLimit = FluidAmount.millibuckets(250).toPlatform();
```

`FluidAmount` supports buckets, millibuckets, droplets and bottles. It can also be used on the various FluidTank methods.

`toPlatform()` converts to the loader's native unit. A bucket is 81,000 droplets on Fabric and 1,000 millibuckets on NeoForge. Bottles are 27,000 droplets (1/3 bucket) on Fabric and 250 millibuckets (1/4 bucket) on NeoForge.

The new `balm:fluid_amount` integer and float providers expose the same conversion for data-driven registries:

```json
{
  "type": "balm:fluid_amount",
  "value": 1,
  "unit": "buckets"
}
```
