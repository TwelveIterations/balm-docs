## Overview

Minecraft 26.1 comes with a lot of toolchain changes, such as a new Loom plugin (`net.fabricmc.fabric-loom`), ForgeGradle 7, Java 25 and deobfuscated names.

You will have to follow the individual mod loaders' migration guides to update your build setup. For reference, you can also compare against these commits [6533615](https://github.com/TwelveIterations/ForgivingVoid/commit/653361502383838cec883df37d9ab0b85519f571), [32904da](https://github.com/TwelveIterations/ForgivingVoid/commit/32904da5c8bf7b32c333cdf2bedf97c685161173) in one of Blay's projects to get an idea of what changes are required.

In terms of code migrations, there are a few bigger changes in Minecraft (like the introduction of `ItemStackTemplate`), but Balm itself has not undergone any significant changes.

## ⚠️ Known Issues

### Custom `BlockStateModel`s are currently disabled on Fabric

Custom models will not resolve, which may lead to crashes when they are used. They will be re-enabled once Fabric ports its model loading API.

### Inbuilt Mod Compatibilities are currently disabled

Compatibility with ModMenu, Jade, WTHIT, Trinkets, Cloth Config, and Configured has been disabled temporarily.

This is due to the many class and package renames in Minecraft 26.1 as well as the shift to deobfuscated names that make it impossible to compile against older versions.

These integrations will be re-enabled as those mods are ported.

### Data Attachments are not available on Forge

Forge does not have a native system for data attachments like Fabric and NeoForge. Balm may provide a basic implementation in the future, but right now attempting to access data attachments on Forge will crash.

### `/balm export icons` is not yet functional

The command has not yet been updated to Minecraft's rendering changes.

## Breaking Changes

### `BalmVillagerTradeRegistrar` has been removed

Minecraft supports data-driven villager trades now.

## AI Summary

This summary was automatically generated and proofread by a human, as a more detailed alternative to the curated migration guide above.

- Removed API: villager trade registrar
    - Removed `BalmVillagerTradeRegistrar`.
    - Removed `BalmRegistrars#villagerTrades(...)`.
    - Removed `BalmModule#registerVillagerTrades(...)`.
    - Migration: move villager trade additions to datapack/vanilla trade data pipeline.
- Breaking API change: block color registration
    - `BalmBlockColorRegistrar#register(...)` now takes `List<BlockTintSource>` instead of `BlockColor`.
    - Migration: replace old BlockColor registrations with new tint-source list registration.
- Breaking API change: crafting remainder hook
    - `BalmHooks#getCraftingRemainingItem(ItemStack)` now returns `ItemStackTemplate` (was `ItemStack`).
    - Migration: call `.create()` where you need an actual `ItemStack`.
- Type change: custom chest material API
    - `CustomChestMaterials` now uses `SpriteId` instead of `Material`.
    - Migration: update providers and registrations to return/pass `SpriteId`.
